# BP follow-up: literal UTF-8 Tool argument (initial proposal)

The bounded BQ prototype now implements a unified numeric/string declaration and a declared JSON string-leaf argument; see [BQ evidence](experiments.md#bq-unified-bound-string-tool-argument-2026-10-15) for the actual API and limitations. The text below is retained as the original design hypothesis, not as an exact description of the implementation.

Decision gate: BO prints a declared JSON string leaf, but the numeric Tool ABI still cannot call the real read-only `read_file(path: str, offset: int = 1, limit: int = 2000)` Host API unchanged. BN's audited response is a dictionary (including `content` and `total_lines`, or an error), with task-relative path authorization, protected-path checks, redaction, pagination and deduplication in the Host. This proposal describes one optional, explicitly Host-bound literal-path call; it neither implements it nor claims unchanged private-script admission. Dynamic paths, list loops, imports and generic Python strings remain out of scope. Proceed only after a Host-owned fixture can enforce the real permission/error/bound contract.

Proposed public addition (names illustrative; existing signatures unchanged): a separate `StringToolSchema { id, name, literal_argument: "path", result: JsonTyped(...) }`, and `Provider::allows_string_tool(id) -> bool` plus `Provider::call_string_tool(id, path: Arc<str>) -> impl Future<Output = Result<Reply, TaskError>> + Send`, both default-deny. Keep `ToolSchema`, `Provider::allows_tool/call_tool(id, [i64; 2], count)`, `HttpProvider` and existing implementers source-compatible. The string ID namespace must be disjoint from numeric IDs at combined schema validation; the Host binds the path callback to the task capability, and the provider validates the ID and path again. A declared name/ID never authorizes an operation. Do not route the path through an `i64`, URL, fixed global or a numeric Tool ID. A second literal-only argument (e.g. offset) is not in this first slice; default pagination is the Host's, not a substituted interpreter rule.

Frontend accepts precisely `tools.<declared>("literal")` for this declaration, with exact positional or named `path` binding, bounded source/literal bytes and valid UTF-8. Reject computed/local paths, mixed numeric calls, `**kwargs`, loops and unsupported spellings; original `read_file(...)` spelling would require a separately Host-declared static global alias, never automatic name import. Sealed IR/Plan carries an index into a per-program immutable `Arc<str>` owner (not an arbitrary pointer); lowering emits a distinct suspension status, sharing JSON root storage and existing `JsonTyped` path selection/BO print. Validate duplicate IDs, names, path count and response bounds at preparation; compile only referenced capabilities. A dedicated cold-path plan/dispatch branch leaves existing numeric call lowering, `[i64; 2]` and hot-path checks unchanged. Benchmark old requests only if this actually lands; there is no predicted speed benefit.

At each string-call boundary, check cancellation and `tool_calls`, then `allows_string_tool`; clone the literal owner into the spawned future (`async move` owns `Arc<str>` and provider) before awaiting its oneshot receiver. If the task is cancelled, dropping the receiver/frame does not drop the argument: the detached operation retains it through actual completion. The Host adapter must also bound concurrent detached work and reply size, apply its normal path validation/redaction/dedup/error mapping, and return `Reply::Json(Bytes)` or `TaskError`. Reuse JSON owner memory accounting, validated string path and BO's atomic stdout byte cap including newline; an oversized printable reply can fail with `Budget` and preserve earlier output. Match native/tape effect order, auth, failure and cancellation behavior.

First gate: a literal-path read-only local fixture with allowed, denied, missing, oversized, escaped/UTF-8 and delayed/cancelled responses on both backends, including weak-owner/late-completion checks and unchanged numeric regression. Only after this is functional should a complete unchanged source be tried; this limited call alone does not solve dynamic path iteration or original global-call spelling.
