# Opt-in fixed-width record scans (AY)

The existing Quote/v1 path remains the default API and ABI. Under `tool-json`, a Host may declare `ResultSchema::Records(RecordSchema)` for a Tool; the Tool returns an immutable `RecordBuffer` rather than JSON or a scalar. The schema is a bounded list of named i64/bool fields with byte offsets and a row stride. Both are multiples of eight, fields fit inside the stride, names are unique, and layouts are validated once at preparation. Gaps and field reordering are supported. No dynamic field names, nested/variable fields, or row objects.

A record buffer owns contiguous aligned words and its declared schema. Import accepts little-endian bytes with whole-row length and bounded row/byte counts; bool cells are checked at import. At each Tool completion the Host checks authority, reply kind, schema identity and combined live-owner byte budget before installing the owner. The existing QuoteBuffer, `Provider::load_quotes`, and `tools.load_quotes` remain unchanged. Record and Quote owners share the existing buffer slots and liveness; no buffer pointer survives its owner.

The frontend binds a loop variable to its buffer's declared field map while compiling the loop. It lowers field access to a fixed byte offset and the loop to a fixed stride, reused by both native and tape backends. Native code retains the existing scan bounds/chunk control and uses direct fixed-offset loads. Tape reads an aligned word at the prebound index. Preparation rejects unknown fields, invalid operations and ambiguous rebinding. Both backends preserve source-order scalar evaluation, effect suspension, row fuel, cancellation and last-use release.

Migration: existing Quote clients and benchmarks need no changes. Opt-in callers construct a schema, use `compile_with_tools` / `prepare_with_tools`, implement `Provider::call_tool` and return `Reply::Records`. The Host explicitly authorizes the tool ID; a declaration is never a capability. Benchmarks should compare the unchanged Quote path and a complete new Tool-record preparation plus execution, not re-label Quote data as a new format.

The exposed diagnostic IR shape grows a stride vector and a Tool-record discriminator; callers manually constructing `Program` or matching `Stmt::Tool` exhaustively must update. The supported source/compiler/Provider Quote API does not change. No migration of existing Quote data is required.
