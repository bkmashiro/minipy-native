# AS integration: opt-in Tool/JSON and narrow string contains (2026-10-15)

## Decision and production boundary

Retain the AH/AJ/AN/AR functional slice for focused review, behind `tool-json`; leave the default feature set unchanged. This integrates existing experiment commits, not a fresh optimizer or backend. `main` at the integration fork was c3dff6a; AH `f7167ad` is an ancestor of AJ `a780931`, AN `79bfcf8`, AO `3b6b800`, and AR `2472681`. One merge of AR brings each once; AL and AO's failed optimization candidates were already withdrawn, not production code. No new syntax beyond those reviewed experimental commits, no website/frozen benchmark/Pysolate changes. Current `origin/main` has subsequent documentation-only commits and is not overwritten; the lead decides final main merge.

Production diff from c3dff6a: `Cargo.toml`/lock add optional bytes/sonic-rs/HTTP dependencies and `tool-json`/`json-allocation-profile` feature switches; new `tool.rs`, `json_view.rs`, `http_provider.rs`; focused changes to `frontend.rs`, `ir.rs`, `codegen.rs`, `interpreter.rs`/`tape.rs`, `runtime.rs`, `provider.rs`, `error.rs`, `lib.rs` and optional debugger compatibility. Feature off: legacy Quote/scalar code paths with no HTTP dependency or JSON State. Feature on: Host-supplied finite Tool declarations and per-task authorization, statically bound borrowed JSON leaves, scalar print/discard, a single JSON UTF-8 string-leaf `"literal" in leaf` operation, and a shared I/O-enabled HTTP service. No generic string Value, containers, array language runtime, kernel registry, alternate scheduler or user URL access. Prior typed-array and scheduler-tuning negative results stay withdrawn. Research reports/fixtures in the merged history are evidence, not more production mechanisms.

## Integrated bounded cost evidence

Apple M4, macOS 26.4.1, rustc/cargo 1.93.1 (string bench built with existing 1.96.0), three independent process pairs in AB/BA/AB order for unchanged old `fastpath_probe.rs` (identical SHA-256 in baseline/current). All builds reused `/Users/yuzhe/projects/minipy-native/target`, one build job, offline/locked, no overlapping performance builds. Baseline c3dff6a and integrated default/feature are separate release executables; time-only Tokio driver on all old-path comparison arms. Each old cold cell compiles source, executes with ready 1,000-row provider, validates/consumes stdout and cleans up for 20 requests/process; prepared is a separate diagnostic at 1,000 requests/process. The tiny scalar prepared variation is within this limited observation; no stable significant old default-path regression is established. A within-feature I/O-enabled driver control keeps all fairness yields: weighted native prepared ~16.828 us and tape ~22.975 us, against time-only ~2.111/~8.590 us. This is a real cost for an I/O-enabled Host, not a reason to disable I/O on actual HTTP tasks. The old ready-provider measurement does not include a socket or HTTP response.

The few-field valid JSON source path in `json_probe` uses actual native/tape compilation and ready async Provider, bound JSON lookup, stdout and cleanup; three independent timing processes, 3 batches per cell. Cold tape/native: 10.504/85.068 us, prepared 0.963/0.902 us. The strong parser-only comparison on the same resident valid input: sonic lazy 0.157 us, sonic typed 0.501 us, serde typed 0.548 us, serde DOM 0.976 us. Parser-only and source-to-result figures are different cost boundaries; they must not be divided into a backend speed ratio. The array-1000 typed decoder negative result from AH still rules out expanding to a lazy array interpreter.

The integrated string probe includes Monty with Host JSON-to-dict conversion and a stronger Host-direct-bool comparator: their provider adapter's `serde_json` decode, dict construction, async handoff, stdout and cleanup are timed, while resident input and Tokio creation are outside. Native/tape have real source preparation, borrowed access and stdout in the cold interval; warm excludes preparation. Three independent processes, 20 measured requests/cell/process with alternating engine order; output verified for every request. Median of per-process medians (us): short-hit cold native/tape/Monty-dict 103.020/12.458/12.041; warm 1.417/1.542/4.916. 64-KiB miss cold 115.875/36.438/20.834; warm 25.958/26.000/15.041. Short-path benefit does not generalize to cold compilation or long scans. The Host-direct-bool arm is in raw/summary; it is a different responsibility boundary and cannot be advertised as a generally available Tool API. The synthetically resident Provider excludes network and the decoder difference (sonic lazy first-key versus serde DOM last-key) means valid fixtures alone do not prove full semantic equivalence.

Real localhost `aj_http_probe` executes fetch -> JSON i64 field -> scalar publish -> print on native and tape, two actual HTTP operations/request through a shared pooled client and one same-runtime TCP server. Three independent processes, AB/BA/AB source syntax order; 3 batches/process, 20 cold or 100 prepared requests/batch, one warmup/pool establishment outside each batch. Source-cold tape/native 96.039/183.461 us; prepared 78.851/78.964 us (assigned syntax). Checks every batch's `27\n` checksum, 2×(n+1) responses including warmup, one reused connection and 0 final response merge bytes on these single-chunk replies. The I/O driver remains ON. This is neither a remote API/TLS latency measurement nor a Monty-over-HTTP comparison. No comprehensive PSS/capacity campaign was repeated.

One separate allocation diagnostic process (not a timing executable) reports prepared scalar tape/native 3 calls/84 B and 4/404 B; weighted 9/880 and 11/1216; JSON few 13/1212 and 13/1468, respectively. These are cumulative allocation requests, not retained or peak resident bytes, and do not isolate parser allocations from per-request runtime allocations. Prepared tape logical bytes are scalar 626, weighted 1122, JSON few 1008; native executable code bytes 264/552/424 (code bytes exclude the JIT module and plan). Relative to c3dff6a, feature-enabled tape adds a 32-byte optional-plan/liveness header to old units; default-feature tape remains 594/1090/1114 bytes for scalar/weighted/stateful. AR's JSON State is 128 bytes on this 64-bit target versus pre-string AH's 80, for *every allocated JSON State*, including integer-only JSON tasks; strings additionally initialize a decoded vector only on string plans. Scalar/Quote-only tasks create no JSON State, decoded vector, owner, cache or HttpService. The budget counts decoded capacity with the root and any live Quote buffers. These static/diagnostic sizes are not RSS or PSS.

Owner/lifetime check from the actual implementation: `State::roots` owns Bytes, checked `Range`s index the same immutable owner, and unescaped strings borrow directly while escaped strings decode once into bounded scratch. Prepared liveness drops root/decoded scratch after last use, including before waits; a live alias holds it across waits. Cancellation drops the task state and its owner, while a detached provider operation retains its own permit until real completion. Native/tape tests cover both branches; real HTTP tests cover late completion and shared admission. JSON malformed unvisited suffixes are intentionally not fully validated, duplicate keys resolve first matching key, and bounds protect requested paths; this is not `json.loads` equivalence.

Compilation and all perf invocations ran sequentially, not under another local benchmark. `cargo test --offline --locked --all-features`, `--no-default-features`, all-target all-feature strict Clippy and fmt passed. Both `json_probe` executables have the same source but different features: never use the allocation build for the timing rows. Source-cold has a warmed process/runtime/compiler scratch and resident fixture but a fresh unit per invocation; it is not cold process startup. Neither the old Quote fixture creation nor new payload construction is timed. Static source semantics differ for JSON duplicates/malformed suffixes; both paths validate the same valid fixture output within their respective timed intervals.

The retention decision is for an opt-in, capability-bounded functionality slice and this observed default-path cost; it does not imply that JIT is optimal for JSON/string processing or that HTTP latency has been improved. Main integration and publication remain for the lead after focused review.
